## 1. 需求确认（做什么）

方案书 v2 §7 工作流（v1 保留，不重设计）：

```
用户入库模板（Word/LaTeX/HTML）
    ↓ 自动扫描占位符
生成 JSON Schema
    ↓ AI 按 schema structured output 受约束产出数据
    ↓ 引擎渲染（docxtpl / md_to_word / XeLaTeX）
输出保真文档
```

### 1.1 模板分类（v1 §5.2）

| 分类 | 说明 | 示例 |
|---|---|---|
| 全局 | 平台内置，不可删除 | harryopo-paper / harryopo-report |
| 场景 | 按用途组织 | 论文、报告、公文、合同、信函、简历 |
| 用户自定义 | 用户上传 | 某公司公文模板.docx |

### 1.2 v1 支持格式与引擎

| 格式 | 占位符语法 | 渲染引擎 | 反解工具 |
|---|---|---|---|
| `.docx` | Jinja2（`{{}}` / `{% for %}`） | docxtpl (`template_render.py`) | `schema_extractor.py` ✅ 已有 |
| `.tex` | harryopo 占位符约定（本期定义） | XeLaTeX (build.ps1) | 规则引擎 + LLM 补语义（M2） |
| `.md` | MD 中间态约定 | md_to_word / convert.py | 结构扫描（`#`/`$$`/`![]`） |

## 2. 业界调研发现（支撑依据）

### 2.1 双轨框架 —— 与本项目 manifest 思路直接同构 ⭐

**arXiv:2606.23107《A Dual-Track Framework for Template-Constrained LaTeX Conversion》**（港科大广，2026-06）

- **离线轨**：把模板约束提取为 **reusable manifest**（可复用清单）
- **在线轨**：混合执行管道 —— **确定性语法走规则引擎，LLM 仅用于推理密集部分**（语义元数据、参考文献）
- 验证：7 模板 × 56 论文，编译成功率显著高于纯 Pandoc / 纯 LLM 端到端
- **结论映射**：本项目 manifest.json 即"可复用清单"；AI structured output 即"LLM 只做语义"，渲染走模板引擎即"规则引擎"。**思路完全一致，已被学术验证**。

### 2.2 TransLaTeX —— 模板反解的验证环节参考

**ACL 2025 SciProD-LLM《TransLaTeX: Exposing the Last-Mile Execution Gap》**

- 占位符**保护 → 重插入**机制（防 LLM 改坏结构）
- 三级验证：① PIS 占位符完整性（1:1 对应）② 编译校验（latexmk）③ 视觉校验（LLM-Vision / 人工）
- **结论映射**：LaTeX 模板反解后必须做"占位符完整性 + 编译通过"双校验；docxtpl 的 `validate` 已是 Word 侧对应物

### 2.3 Schema Registry 模式（nexus）

- `schema.register` / `schema.deregister` 事件 + `before:llm.request` 挂钩自动附加 schema
- 三层设计：**schema 声明 → 请求打标 → provider 执行**
- **结论映射**：注册表 = schema 声明层；AI 调用时按模板名取 schema 附加约束 = 请求打标层

### 2.4 严格校验参考（M365 Copilot / model-catalog）

- **M365 Copilot declarative agent manifest**：JSON Schema 校验，**未知属性导致整个文档无效**（严格模式）
- **model-catalog**：descriptor 验证脚本 + 枚举约束
- **LLM Structured Outputs 实测**：OpenAI strict mode 失败率 <0.1%；Claude 无原生 strict（需工具模拟 + 自校验）；生产建议 temperature 0.0–0.2
- **结论映射**：schema 校验必须双保险（provider strict + 本地 validate），`docx_template.py validate` 已有，注册表沿用

### 2.5 统一元数据源模式

- 跨格式元信息对齐：**YAML 中央元数据 → LaTeX `\gdef` / Pandoc `--metadata-file` / Word `core_properties`**
- PDF-Extract-Kit `.tpl` 模板引擎（config 驱动 + Jinja2 语法）
- **结论映射**：manifest.json 作为模板的"中央元数据"单点，各引擎从它取 schema/渲染参数 —— 与 v1 §5.1 设计一致

### 2.6 调研启示汇总 → 设计决策

| 启示 | 采纳为设计决策 |
|---|---|
| reusable manifest + 混合管道 | manifest.json 为模板唯一元数据源；LLM 不直接动模板 |
| 占位符保护 + 三级验证 | render 前 validate；LaTeX 反解需编译校验 |
| schema 声明/请求打标分离 | `get_schema(id)` 供 AI structured output 使用，模板文件与 schema 解耦 |
| 未知属性无效（严格模式） | manifest 校验：未知字段拒绝加载，防止手改 JSON 出错 |
| 统一元数据源 | 注册表单点管理，引擎按 id 取 schema |

## 4. manifest.json 结构设计（v1）

### 4.1 单模板条目（registry 内每模板一个 manifest 字段/文件）

```json
{
  "manifest_version": "1.0",
  "id": "harryopo-report",
  "name": "harryopo 报告模板",
  "version": "4.0",
  "format": "latex",
  "category": "全局",
  "engine": "harryopo-xelatex",
  "source": "builtin",
  "template_path": "latex/report/example-report.tex",
  "schema_ref": "schemas/harryopo-report.schema.json",
  "preview": "previews/harryopo-report.png",
  "placeholder_syntax": "tex-placeholder-v1",
  "tags": ["学术", "正式"],
  "usage_count": 0,
  "created_at": "2026-08-28",
  "updated_at": "2026-08-28"
}
```

字段说明（严格校验白名单，未知字段拒绝加载 —— 对齐 M365 严格模式）：
- `id`: 全局唯一（格式 `{来源}-{名称}`，如 `user-公文模板`）
- `format`: `docx | latex | markdown | html`
- `engine`: `docxtpl | md_to_word | harryopo-xelatex | html`
- `schema_ref`: JSON Schema 相对路径（docx 由 extract 自动生成；latex 由规则引擎+LLM 生成）
- `source`: `builtin（全局）| user（用户自定义）| market（市场，M3）`

### 4.2 注册表目录结构

```
templates/registry/
├── manifest.json            # 索引（所有模板条目的数组，含校验）
├── word/                    # Word 模板库
│   ├── 公文模板.docx
│   └── schemas/公文模板.schema.json
├── latex/                   # LaTeX 模板库（harryopo 内置 + 用户）
│   ├── report/              # 模板文件（.cls/.sty 共享引用 templates/cls/）
│   └── schemas/harryopo-report.schema.json
├── markdown/                # MD 中间态模板
├── html/                    # HTML 模板（阶段 3 编辑器用）
└── previews/                # 预览图（M3 自动生成）
```

### 4.3 内置模板首批条目（M1）

| id | format | 说明 |
|---|---|---|
| `harryopo-paper` | latex | 双栏论文（example-paper-twocolumn.tex） |

## 5. 技术方案（v1 实施）

### 5.1 新文件：`scripts/word/template/template_registry.py`（纯 stdlib）

```
核心数据结构：Registry（manifest.json 的加载/保存/校验）
API：
  add(template_path, category, name?)        # 按格式路由入库
  list(format?, category?, query?)           # 过滤列表
  describe(template_id)                      # 详情（含 schema 摘要）
  get_schema(template_id) -> dict            # 供 AI structured output
  search(query)                              # 名称/标签模糊匹配
  remove(template_id, force?)                # 删除（builtin 需 force）
  update_usage(template_id)                  # 使用计数
入库路由（add）：
  .docx → schema_extractor.extract_schema() → schema 存 schemas/ → 写 manifest
  .tex  → M1: 仅登记（schema 空，M2 生成）；M2: 规则引擎扫描 + LLM 补语义
  .md   → 结构扫描（# 层级 / $$ / ![] / | 表格）→ 生成字段清单
校验：
  load 时白名单字段校验（未知字段 → 拒绝 + 报错定位）
  schema 存在性校验（schema_ref 指向文件必须存在）
```

### 5.2 集成点（不动现有渲染代码）

| 集成 | 方式 |
|---|---|
| docx_template.py | add 入库流程调用其 extract；render 流程不变 |
| office.py | `--template <id>` 参数：按 id 解析出 template_path + schema，再走既有渲染 |
| SKILL.md | 新增"场景D：按模板出文档"流程（list → describe → AI 按 schema 产出 → render） |

### 5.3 CLI 设计

```
python template_registry.py add  ./公文模板.docx -c 用户自定义
python template_registry.py list [-f docx] [-c 用户自定义]
python template_registry.py describe harryopo-report
python template_registry.py schema harryopo-report -o schema.json
python template_registry.py search 报告
python template_registry.py remove docxtpl-example --force
```

### 5.4 LaTeX 占位符约定（本期定义，M2 反解依据）

harryopo LaTeX 模板中以注释形式声明占位符（对 XeLaTeX 无副作用）：

```latex
% [harryopo:placeholder] title, 文档标题, required
% [harryopo:placeholder] author, 作者列表, required, array
\title{\gdef\@title{...}}  % 引擎注入点（参考 §2.5 统一元数据源）
```

规则引擎（M2）扫描 `% [harryopo:placeholder]` 注释 → 生成初版 schema（类型/必填）；LLM 仅补字段中文描述与示例。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| LaTeX 模板占位符无统一语法，通用反解不可行 | 本期只定义 **harryopo 占位符约定**（注释声明），不做通用 LaTeX 反解；用户 .tex 模板走 M2 双轨 |
| schema 字段 description 为空 → AI 不理解语义 | 沿用 docxtpl 工作流：AI 产出前先向用户确认字段含义；M2 由 LLM 补描述 |
| LLM 输出漂移（多 provider 无 strict） | 双保险：provider structured output（若有）+ 本地 `validate`（docx_template.py 已有） |
| 模板更新后旧 data.json 失效 | manifest `version` + schema `schema_version` 双重记录；describe 展示版本差异 |
| 注册表 JSON 被手改损坏 | 白名单严格校验 + 未知字段拒绝加载 + 加载报错定位 |
| builtin 模板被误删 | builtin 需 `--force` 才可 remove |
