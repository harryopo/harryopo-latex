# archify 开源框架流程图调研报告

> 调研日期：2026-08-14
> 源码位置：`opensource-reference/archify/`（git clone，v2.14）
> 上游：Cocoon-AI/architecture-diagram-generator (MIT, v1.0)
> 参考价值：⭐⭐⭐⭐⭐ —— 与我们的 flowchart-generator / super-diagram 目标完全同构（LLM 产 JSON → 代码渲染 → 质量兜底），其质量校验体系是目前开源同类中做得最完整的

---

## 一、项目定位与架构总览

archify 是一个 **agent skill**：LLM 按"快速写作路径"产出小型 typed JSON（类型化中间表示）→ CLI 渲染成**自包含交互式 HTML（内联 SVG）**。支持 5 类图：

| 类型 | 用途 |
|---|---|
| `architecture` | 组件、服务、云/安全边界、基础设施 |
| `workflow` | 流程、审批门、工具调用、CI/CD |
| `sequence` | API 调用链、请求生命周期、异步追踪 |
| `dataflow` | 数据管线、ETL/ELT、血缘、治理 |
| `lifecycle` | 状态/状态机、重试、等待/终态 |

### 三段式架构（全项目最核心的设计思想）

```
布局判断靠 agent       路由判断靠代码         质量兜底靠校验
┌──────────────┐   ┌──────────────────┐   ┌──────────────────────┐
│ LLM 显式放坐标 │ → │ geometry.mjs 纯函数 │ → │ 8+ 类校验全部带      │
│ pos:[x,y]    │   │ 正交路由/端口扇出/避障 │   │ 错误码+subject+evidence │
│ 或 row/col   │   │ 多候选+过滤排序      │   │ +supportedFixes      │
│ 不做自动布局   │   │ 确定性、可复现       │   │ （维修单据 repair     │
│              │   │                    │   │  receipt）           │
└──────────────┘   └──────────────────┘   └──────────────────────┘
```

**关键洞察**：archify **不追求自动布局**（那是最难的、效果最不可控的部分）。它把布局责任明确交给 LLM（显式坐标），把几何算法（路由、避障、扇出、校验）交给确定性代码。校验失败时给出**可操作的修复建议**而非简单报错——让 LLM 能根据单据自我修复。

这与我们 flowchart-generator v0.4.0 回归"官方显式坐标"的决策完全一致，但 archify 在**校验深度**上远超我们。

## 二、关键算法详解（按可借鉴价值排序）

### 1. 自动端口扇出 automaticPortSpread（⭐⭐⭐⭐⭐ 我们最缺）

**解决什么**：多条连接共享同一个组件端点时，箭头全部堆在同一点（视觉粘连、无法区分哪条线连哪个端口）。

**算法**（geometry.mjs:1102）：
1. 按 `组件id + 侧(left/right/top/bottom)` 分组共享端点的关系（只处理 auto 路由，显式 via/channelX/labelAt 跳过）
2. 每组 <2 条不扇出
3. 排序：按**对端中心的坐标**排序（确定性）；坐标相同再按 relation id 字典序
4. `spacing = min(14, (边长 - 2×16gutter) / (n-1))`，spacing ≤ 0 则放弃
5. 偏移 `offset = (index - (n-1)/2) × spacing`，绕侧中点**对称分布**
6. 只返回"共享自动中点锚"的端点，非共享端点不动

**配套** `automaticPortRhythmBridge`（geometry.mjs:1031）：近平行端口（top-top 且 x 差 <16px）用 **24px 端点 stub + 16px 外部通道桥** 绕行，而不是制造一个微小的锯齿 dogleg（<8px 段不可读）。

### 2. 确定性路由 routeVia（⭐⭐⭐⭐⭐ 多候选+过滤）

**4 种路由**：`straight` / `orthogonal-h`（先水平后垂直）/ `orthogonal-v` / `auto`。

**auto 的候选生成顺序**：
1. 直连（仅当 deltaX <4 或 deltaY <4 且满足端点侧契约）
2. rhythm bridge（近平行端口外部通道）
3. 平行侧端点外部通道（两端都在 left/right 且 y 差 <16px → 走 channelY 外侧）
4. 两种 dogleg：`horizontalFirst`（先 midX 垂直）和 `verticalFirst`（先 midY 水平）
5. side-aware bridge（显式 fromSide/toSide 时的有界外部通道候选）

**过滤条件**（所有候选必须全过）：
- `routeHonorsEndpointSides`：**侧是方向契约**——首尾段必须沿命名方向垂直进出
- `routeClearsEndpointComponents`：不穿自身端点组件
- `routeClearsComponents`：不穿任何第三方组件
- `collinearBacktrack`：消除回头线（180° 折返）
- `collectRouteRhythmIssues`：showcase 下内部段 ≥16px

**失败闭环**：全被挡时返回 `sideSafe[0] || sideAware[0] || horizontalFirst` 中最好的端点安全路由，**让校验报告真实障碍**，而不是静默出错。

### 3. 质量校验体系（⭐⭐⭐⭐⭐ 我们差距最大）

全部校验函数为纯函数，输出问题数组；问题全部带 **稳定错误码 + 精确 subject + 测量 evidence + supportedFixes（只允许的修复手段）**。

| 校验 | 错误码 | 内容 | 触发条件 |
|---|---|---|---|
| 边穿节点 | `clean-flow/edge-through-node` | 边穿过无关不透明节点 | **硬失败**（与 profile 无关） |
| 端点方向 | `clean-flow/endpoint-side-direction` | 首尾段切线进入端口 | 硬失败 |
| 交叉 | `composition/proper-crossing` | 两条无关边相交 | showcase 失败 |
| 共走廊 | `composition/ambiguous-corridor` | 无关边视觉合并（共线重叠 ≥8px） | showcase 失败 |
| 贴边框 | `composition/container-border-run` | 长边沿容器边框运行 | standard+ 失败 |
| 微段节奏 | `composition/micro-segment` | 段 <8px / 内部段 <16px | showcase 失败 |
| 标签遮路线 | `composition/label-route-clearance` | 标签 mask 盖住另一条路线 | showcase 失败 |
| 组件重叠 | — | 两组件 <8px apart | 硬失败 |
| 标签超宽 | — | 文本超过盒宽 | 硬失败 |
| 视图外 | — | 组件/边界超出 viewBox | 硬失败 |

**quality_profile 分级**：`standard`（可渲染、警告不阻塞）vs `showcase`（9 项检查 0 错误 0 警告）。

**维修单据结构**（repair receipt）：
```json
{
  "code": "composition/label-route-clearance",
  "severity": "error",
  "message": "label \"approved replay\" masks route \"failure sample\" ...",
  "subject": { "diagramType": "dataflow", "path": "/flows/1", "identity": "web-clickstream" },
  "evidence": { "labelRect": {...}, "routePoints": [...] },
  "supportedFixes": ["apply labelAt", "adjust labelDx/labelDy", "adjust labelSegment"]
}
```

**修复顺序契约**（authoring-contract）：
1. schema / quality_profile 错误
2. 节点重叠 / 越界
3. 穿节点 / 端点方向
4. 交叉 / 共走廊 / 贴边框 / 节奏
5. 标签遮挡（node → label → route）

### 4. 文本适配 text-fit.mjs（⭐⭐⭐⭐ 对应我们"卡片大文字空"）

**两段式**：
- `fittedNodeFontSize(text, width, preferred, minimum)`：渲染时**缩小字号**到能放进盒内的最大值（floored at minimum）。`fontSize = min(preferred, (width-8) / (textUnits × 0.6))`。普通超长文本直接变小，不重叠。
- `minimumNodeTextWidth`：验证"缩到最小字号也放不下"的文本 → **拒绝**并报错。

**CJK 测量** `textUnits`（utils.mjs）：全宽字符（中文/日文/emoji，正则覆盖 CJK 区段）按 **2 单位**计，ASCII 按 1 单位。这是中文适配的核心。

**宽度系数**：`widthFactor: 0.6` px/单位/px字号，`horizontalPadding: 8`。

### 5. 布局：显式坐标 + grid 兜底（⭐⭐⭐⭐ 与我们 v0.4.0 同向）

- 自由放置：`pos:[x,y]` **必须**显式给出，缺了就报错（不做估算兜底布局）
- grid 模式：`layout: {mode:"grid", origin:[40,80], cols:4, gapX:30, gapY:40, cellW:130, cellH:64}`——**固定格子数学，非自动布局**；`pos` 优先，`row/col` 是可选提示
- 默认组件尺寸 `defaultW:120, defaultH:60`
- 校验：col 越界、row/col 非负、同格重复、pos 与 grid 混用规则

### 6. 边界自动计算（⭐ 小技巧）

`boundaryRect`：按 `wraps` 成员取 min/max 包围盒 + `pad`（30px 上/左/右 + 20px 底部额外，即"30/50 rule"，曾是手算脚枪坑）。`kind: "security-group"` 圆角 8，普通边界圆角 12。

### 7. 自动 viewBox（⭐）

fit 所有组件+边界几何 → 算图例 footprint → 图例放不下就扩宽 viewBox。图例 `legendH: 28`。

### 8. 原子交付 deliver（⭐⭐⭐ 工程化典范）

`deliver` 流程：读 spec 一次 → 写私密候选快照（同目录）→ 渲染快照 → 跑完整检查 → **全过后才原子替换目标**；失败则保留上一版可信 artifact、删除私有状态、绝不调用 opener。收据带 SHA-256 + 字节数（spec 与 artifact 各一份）。

### 9. 诚实视觉检查 visual-check（⭐⭐⭐ 印证我们的硬约束）

用 Chrome DevTools pipe 测量 4 档分辨率（1440×900 / 1600×1000 / 1920×1080 / 2048×1320）的 containment（scrollWidth ≤ innerWidth 且 scrollHeight ≤ innerHeight）+ 明暗截图。**收据永远报 `visualReview: "pending"`**——截图只是证据，绝不冒充人工视觉审查。这正印证了 CLAUDE.md 硬约束"代码层优先，反对花哨验证"：自动化证据 ≠ 视觉通过。

## 三、测试与契约体系（⭐⭐⭐⭐ 工程质量的保障）

- `layout-rules.test.mjs`：**每个 case 恰好制造一个违规**，断言非零退出 + 期望消息子串 + 不崩溃（不出现 TypeError/is not a function）。错误消息契约测试：必须带数字阈值 + 修复动词（`\d+px|at least \d+|less than`）。
- **收缩测试**：改长文本 → 渲染 → 从 HTML 正则提取 `font-size`，断言真的 < preferred 且 ≥ 6（验证渲染端行为，不只是校验端）。
- `delivery-contract.test.mjs`：原子交付失败不破坏旧 artifact。
- 错误路径注释：ajv schema 路径 `/nodes/3/label` 注解成 `/nodes/3 (id: "router") /label`，方便 LLM 定位修复。
- 基准测试 `benchmarks/ordinary-model-floor/`：用普通模型跑 5 类图，测"普通模型也能过"的能力下限。

## 四、与我们的差距对照

| 维度 | archify | flowchart-generator / super-diagram | 差距 |
|---|---|---|---|
| 布局策略 | 显式坐标，缺 pos 就报错 | v0.4.0 显式优先 + 估算兜底 | 基本同向 |
| 端点扇出 | 自动端口扇出（对称分布+角留白） | 箭头固定组件中心线 | **缺** |
| 路由 | 多候选+过滤（stub/通道/dogleg/bridge） | 手写坐标 + 简单连线 | **缺** |
| 质量校验 | 8+ 类带修复建议、错误码、profile 分级 | 仅脚本级验证（引用/格式） | **差距最大** |
| 文本适配 | 渲染时缩小字号 + 下限校验 | 显式坐标+估算宽度 | 有概念无系统化 |
| CJK 测量 | textUnits 全宽 2 单位 | 估算（CJK≈1.0×字号） | 接近 |
| 交付 | 原子替换 + SHA 收据 | 直接写文件 | **缺** |
| 视觉检查 | DevTools 4 档 containment + 截图收据 | 无（按硬约束不做目检） | 可借鉴"证据化" |

## 五、可迁移到我们 skill 的清单（按优先级）

1. **P0 质量校验体系**：给 flowchart-generator gen.py / super-diagram render_v2.py 增加 `--validate` 模式，实现：
   - 边穿节点（硬失败，`segmentIntersectsRect` 几何已有实现参考）
   - 组件重叠（<8px）
   - 标签超宽（textUnits + 宽度系数）
   - 引用有效性（我们已部分有）
   - 每条失败带错误码 + subject + evidence + supportedFixes
   - 错误信息契约：数字阈值 + 修复动词

2. **P0 自动端口扇出**：解决我们多箭头堆同一点的问题。算法可直接移植（分组→排序→对称分布→16px 角留白），约 50 行。

3. **P1 确定性路由**：straight/orthogonal-h/orthogonal-v/auto + 候选过滤（端点侧契约 + 避障 + 回头线消除）。我们 v0.4.0 手写坐标已覆盖大部分场景，可逐步引入 auto 兜底。

4. **P1 fittedNodeFontSize**：渲染时缩小字号而不是仅校验宽度——直接解决用户反复反馈的"卡片大文字空"的另一种解法（我们已用显式坐标+内容驱动尺寸，可二者互补）。

5. **P2 原子交付 + 收据**：写文件前先渲染到临时名、校验通过再 rename。

6. **P2 错误消息契约测试**：测试每个校验 case 恰好一个违规 + 消息含阈值与修复动词。

## 六、结论

archify 的可借鉴核心不是某个具体算法，而是**"布局判断靠 agent、路由判断靠代码、质量兜底靠校验、失败带维修单据"**这套分工哲学。它把最难的自动布局外包给 LLM 的显式坐标，把确定性最强的几何算法留给代码，再用带修复建议的校验闭环让 LLM 自愈。这对我们的 flowchart-generator（架构图/时序图）是最直接的升级路线：**先补齐质量校验 + 端口扇出，再考虑确定性路由**。
