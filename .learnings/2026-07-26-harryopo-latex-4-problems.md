# 2026-07-26 harryopo-latex 4 个问题修复

## 背景
合并 harryopo-convert 到 harryopo-latex 后，用户调用时遇到 4 个格式问题：
1. 小标题开头段落内容不需要 0.1; 0.2 这种编号
2. 不要显示 "本文由 harryopo-convert 自动生成" 字样
3. 生成表格时越界超出页边距
4. 表名称写在表格的下方，照片的注释也是下方

## 根因 & 修复

### 问题 1：小标题 0.1/0.2 编号
**根因**：ctexart 默认 `\thesection` 显示阿拉伯数字（0.1, 0.2...），原 convert.py 生成的 .tex 使用 `\section{}`、`\subsection{}` 等带编号命令。

**修复**：
- `convert.py`：标题命令改为 `\section*` / `\subsection*` / `\subsubsection*` 系列（无编号），同时用 `\addcontentsline` 仍能进目录
- `harryopo-paper.cls`：`\renewcommand{\thesection}{}` 保险起见（手写 .tex 也生效）
- `harryopo-report.cls`：`\thechapter`、`\thesection` 等都重定义为 `{}`
- `harryopo-report.cls`：`\chaptermark` 中删除 "第\thechapter 章" 前缀

### 问题 2：自动生成字样
**根因**：
- `convert.py` 顶部有 4 行 `Auto-generated by harryopo-convert` 注释
- `assemble_report()` 有 `\introduction` + `本文由 harryopo-convert 自动生成` 的硬编码段

**修复**：
- 删除 paper 和 report 函数顶部的 4 行注释
- 删除 `\introduction` + 自动生成文字的 3 行

### 问题 3：表格越界
**根因**：`_parse_table_to_latex` 使用固定 `tabular{lllc}`，列宽不灵活且总和可能超过 `\textwidth`。

**修复**：
- 改用 `\begin{tabularx}{\textwidth}{>{\raggedright\arraybackslash}X ...}`，列宽按内容自动分配
- 添加 `\small` 控制字号
- 转义表头/单元格的 LaTeX 特殊字符（`&`、`%`、`$` 等）

### 问题 4：caption 位置
**根因**：原表格 `\caption{}` 写在 `\begin{tabular}` 之前（图/表上方）。

**修复**：
- 表格：`\caption{}` 移到 `\end{tabularx}` 之后
- 图片：新增独立行图片识别（`![alt](url)`）作为 BLOCK_FIGURE，生成 `\begin{figure}...\includegraphics...\caption{alt}...\end{figure}`，caption 放在图下方

### 额外问题：split_blocks 段尾贪婪匹配
**根因**：段落边界 lookahead `(?!\n#{1,4}\s)` 只识别单个换行，markdown 中常见 `\n\n## ` 双换行模式被吞入上一段。

**修复**：lookahead 改为 `(?!\n+#{1,4}\s|\n+...)`，允许多个换行作为段落边界。

### 元数据重复问题
**根因**：`## 摘要` 后面的段落里嵌入的 "关键词：..." 行没被识别为已提取的元数据，导致在 PDF 中重复显示。

**修复**：在 paper/report 主循环新增 `keywords_in_text_re` 检测，若段落包含 "关键词：..." 行则剔除该行后再输出。

## 踩坑记录
- PowerShell 调用 xelatex 时 `TEXINPUTS` 必须以 `;` 结尾才能继续搜索 TeX Live 默认路径（否则 ctexart.cls 找不到）
- PowerShell `\` 会被解析为转义符，写 PowerShell 脚本时 `$env:VAR = "..."` 语法
- 编译脚本 `build.ps1` line 120 含 em-dash `—` 字符，PowerShell 命令行调用时可能报错
