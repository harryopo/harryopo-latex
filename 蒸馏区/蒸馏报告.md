## 1. 为什么要蒸馏？

### 1.1 现状

| 工作流 | 优点 | 痛点 |
| --- | --- | --- |
| Word 编辑 | 直观所见即所得 | 格式难统一 / 表格/图片易乱 / 跨平台差异大 |
| LaTeX 编译 | 排版质量高 / 公式强 / 可编程 | 编译门槛高 / 图需手动放位 / 排错成本大 |
| **蒸馏目标** | **格式沉淀** + **图位预留** | **让用户专注内容** |

### 1.2 蒸馏要回答 3 个问题

1. **格式**：原 Word 用什么字体、什么字号、什么颜色？
2. **结构**：章节怎么划分？标题怎么分级？表格什么列宽？
3. **资产**：图放哪里？表什么样式？关键信息从哪段来？

**关键代码**：

```python
# 提取段落 + 样式
for i, p in enumerate(doc.paragraphs):
    style = p.style.name
```

### Stage 2：分析（人工 + 启发式规则）

**分析维度**：

| 维度 | 提取规则 | 原文档特征 |
| --- | --- | --- |
| 标题层级 | 字号 + 字体 + bold 组合 | 1 级 16pt 方正小标宋 / 2 级 14pt Times bold / 3 级 12pt Times bold |
| 正文 | 默认段落 | 12pt Times |
| 题目小标题 | 11pt 黑体 + 加粗 | 蒸馏为 `\subhead` 宏 |
| 字体族 | 字体名直接读取 | 中：方正小标宋/黑体/楷体；英：Times New Roman |
| 编号 | 段落首字符 | `1`、`2.1`、`2.2.1` 手动编号 |
| 表格 | 列数 + 列宽比例 | 多为 3-4 列，首列加粗 |
| 图片 | 上下文段落 | "图N：xxx" 模式 |
| 段落语义 | 段落类型 | 摘要/关键词/引言/章节/段落/列表 |

**风格蒸馏决策**：

- 保留 Word 的 6 章结构 → `\chapter` × 6
- 1.x 节格式 → `\section`（2 级足够）
- 题目小标题 → 自定义 `\subhead` 宏（黑体 11pt 加粗）
- 摘要 + 关键词 → `\begin{abstract}` + 自定义 `\keywords` 宏
- 评审对标表 → `tabularx` 自适应列宽

| 用途 | Word 原字体 | LaTeX 字体命令 | 字号 |

| 关键词 | 黑体 | `\fzht` | 12pt |
| 页眉 | 楷体 | `\fzkt` | small |
| 英文 | Times New Roman | XITS | 全文 |
| 数学 | — | XITSMath | — |

### 3.2 颜色规则

```latex
\definecolor{MainColor}{HTML}{1A365D}    % 主色：深蓝（标题）
\definecolor{SubColor}{HTML}{2B6CB0}     % 副色：中蓝（副标题）

\definecolor{DarkColor}{HTML}{1A202C}    % 暗色：近黑（正文）
```

### 3.3 章节结构规则

```
1 章标题：方正小标宋 16pt（\chapter）
  1.1 节标题：Times bold 14pt（\section）
    1.1.1 小节：Times bold 12pt（\subsection）
      题目小标题：黑体 11pt（\subhead）
```

### 3.4 占位标记规则

| 占位 | 含义 | 替换方式 |
| --- | --- | --- |
| `{占位}` | 1-2 句可填文字 | 直接覆盖 |
| `{引文占位}` | 引出段，30-80 字 | 写引出段 |
| `{摘要占位}` | 整段摘要 | 300-500 字 |
| `{致谢占位}` | 整章致谢 | 4 段致谢 |
| `{风格提示:...}` | 注释，提醒用户怎么写 | 删掉注释，写真实内容 |

### 3.5 图片占位规则

1. 原图复制到 `figures/img_NNN.png`（NNN 顺序编号）
2. 模板中按 `0.95\textwidth`、`0.55\textwidth` 等预设宽度引用
3. 用户覆盖同名文件即可，**不需要改 .tex**
4. 命名不一致时改 `\includegraphics{...}` 的文件名

### 3.6 表格规则

| 场景 | 列数 | 推荐样式 |
| --- | --- | --- |
| 评审对标 | 2 | `l X`（首列加粗，X 自适应） |
| 痛点 × 方案 | 3 | `l X X` |
| 模块详情 | 4 | `c l l X` |
| 数据库表 | 4 | `l X X X` |
| 评审维度 | 2×2 双栏 | 用 `\\` 强制换行 |

## 4. 蒸馏踩坑清单

### 4.1 字体路径

**坑**：`\setmainfont{XITS}[Path=fonts/]` 相对路径以**当前工作目录**为基准，不一定以 `.tex` 文件所在目录为基准。

**修**：在 `build.ps1` 中用 `Push-Location` 切换到 `templates/` 子目录编译，让 `Path=fonts/` 解析为 `templates/fonts/`。

```powershell
# 关键：必须从 templates/ 子目录编译
Push-Location $TemplatesDir
xelatex -output-directory="$SourceDirUnix" "$FullPathUnix"
Pop-Location
```

### 4.2 全角符号冲突

**坑**：`\xeCJKsetup{...}` 中用全角符号【】导致 fontspec 解析失败。

**修**：所有自定义命令一律用 ASCII 花括号 `{}`，不要混用全角【】。

### 4.3 ctex 重复加载

**坑**：`\documentclass[ctexart]` 已经隐式加载 ctex，若 `harryopo-base.sty` 再 `\RequirePackage{ctex}` 会报 `Missing \begin{document}` 致命错误。

**修**：`harryopo-base.sty` 中**不加载 ctex**，仅依赖 ctexart 已加载的 ctex。

### 4.4 CJK 字体族重定义

**坑**：`\setCJKfamilyfont{zhkai}{...}` 与 ctex 默认的 fandol 集冲突，报"already defined"。

**修**：用 `\newCJKfontfamily` 创建独立族（如 `\newCJKfontfamily\hrypkai{...}`），避免覆盖。

### 4.5 XITSMath 副本

**坑**：`unicode-math` 的 `SizeFeatures` 需要 `XITSMath.otf`（无 `-Regular` 后缀），但发行版只有 `XITSMath-Regular.otf`。

**修**：在 `build.ps1` 中自动复制：

```powershell
if ((Test-Path $mathReg) -and (-not (Test-Path $mathOtf))) {
    Copy-Item $mathReg $mathOtf -Force
}
```

### 4.6 PowerShell 路径反斜杠

**坑**：Windows 路径 `D:\ai\latex\foo.tex` 直接传给 xelatex，反斜杠被当转义字符。

**修**：所有路径变量 `-replace '\\', '/'` 转换。

```powershell
$FullPathUnix = $FullPath -replace '\\', '/'
```

### 4.7 overfull hbox（图片溢出）

**坑**：图片宽度 `0.95\textwidth` 时，若有边距影响会溢出。

**修**：用 `0.9\textwidth` 或 `0.85\textwidth` 留余量；或包 `\rlap{}` 让图片延展到边距外。

## 6. 复用方法论

### 6.1 蒸馏另一份 Word 文档

```powershell
# 1. 创建新蒸馏区
$d = "d:\ai\latex\蒸馏区2"
Copy-Item "d:\ai\latex\蒸馏区\templates" $d\templates -Recurse
Copy-Item "d:\ai\latex\蒸馏区\build.ps1" $d\build.ps1

# 2. 复制目标 Word
Copy-Item "D:\我的\新项目.docx" "$d\"

# 3. 改 distill-docx.py 的输入路径
# 4. 运行蒸馏
python $d\distill-docx.py

# 5. 分析 distill-output.txt，手工生成 .tex
# 6. 编译
cd $d
.\build.ps1
```

### 6.2 同一份 Word 改完重蒸馏

1. Word 改完 → 重跑 `distill-docx.py`
2. 比对 `distill-output.txt` 与现有 `.tex` 差异
3. 仅同步修改过的段落（不要全量重生成，避免丢失手工优化）

### 6.3 蒸馏"代码风格 / 排版习惯"到 preamble 片段库

未来积累更多文档后，可以提取出：

- `preamble-academic.sty` — 学术风
- `preamble-business.sty` — 商业风
- `preamble-creative.sty` — 创意风

每个 .sty 是常用包/字体/颜色/命令的集合，换 .sty 即可换风格。
